# Firebase の設定（共有アーカイブ機能）

招待したメンバーだけが見られる・書き込める「共有アーカイブ」を動かすための設定です。
Firebase コンソール（https://console.firebase.google.com/ → `tvxq-live-archive`）で行います。

**この順番で進めてください。** 新しいアプリは古いルールのままでも動きます。一方、古いアプリは新しいルールでは動きません。
そのため「アプリを公開してからルールを更新する」順番にしています。

## 1. Google ログインを有効にする

1. 左メニュー「構築」→ **Authentication** →（初回のみ）「始める」
2. 「Sign-in method」タブ →「新しいプロバイダを追加」→ **Google**
3. 「有効にする」をオンにし、「プロジェクトのサポートメール」に自分のアドレスを選んで「保存」

## 2. アプリの URL を許可する

1. Authentication →「設定」タブ →「承認済みドメイン」
2. 「ドメインの追加」で、普段アプリを開いている URL のドメインを追加する
   （例：`tvxq-live-archive.vercel.app`。`https://` と末尾の `/` は付けない）

※ これを忘れると、ログインのときに `auth/unauthorized-domain` エラーになります。

## 2-2. ログインの戻り先を Google に登録する（iPhone の Safari 対策）

iPhone の Safari は、別のドメインをまたぐログインの途中情報を消してしまいます（`missing initial state` エラー）。
そのためアプリでは、ログイン用のページを `tvxq-live-archive.vercel.app` から配信しています（`vercel.json` で中継）。
この戻り先の URL を Google に登録します。

1. https://console.cloud.google.com/apis/credentials?project=tvxq-live-archive を開く（Firebase と同じ Google アカウントで）
2. 「OAuth 2.0 クライアント ID」の **「Web client (auto created by Google Service)」** をタップ
3. **「承認済みのリダイレクト URI」** の「URI を追加」を押し、次を入力する
   `https://tvxq-live-archive.vercel.app/__/auth/handler`
4. 一番下の **「保存」** を押す（反映まで数分かかることがあります）

## 3. アプリを公開する

`main` にマージすると、Vercel が自動でデプロイします。

## 4. オーナーが最初にログインする

1. アプリを開き、**オーナーのアカウント（`src/lib/firebase.js` の `OWNER_EMAIL`）** で「Googleでログイン」する
2. 初回ログインのとき、旧データ（`archive/allLives`）が自動で新しい形式に移行されます
   - 旧データは消さずに、バックアップとして残します
   - 座席・写真・思い出・Tips は、オーナー本人の記録として移行されます

## 5. セキュリティルールを更新する（初回のみ手作業。以後は手順7で自動化）

1. 左メニュー「構築」→ **Firestore Database** →「ルール」タブ
2. エディタの中身をすべて消し、このフォルダの **`firestore.rules`** の内容を貼り付けて「公開」

これで、招待されていない人は何も見られなくなり、書き込めなくなります。
期限付きのルールではないので、日付が来て止まることもありません。

## 6. メンバーを招待する

1. アプリのヘッダーにある「👥 メンバー」から、友人の Google アカウントのメールアドレスを追加する
2. 友人にアプリの URL を送り、「Googleでログイン」してもらう

※ LINE などのアプリ内ブラウザでは Google ログインができません。Safari や Chrome で開いてもらってください。

## 7. ルールの自動反映を設定する（1回だけ）

この設定をすると、`firestore.rules` を変更して `main` に入れたときに、GitHub Actions がテストを通したうえで自動で本番に反映します。
手順5のように、コンソールに貼り付ける作業がいらなくなります。

1. Firebase コンソールで、左上の歯車（設定）→「**プロジェクトの設定**」→「**サービス アカウント**」タブを開く
2. 「**新しい秘密鍵の生成**」→「キーを生成」を押すと、JSON ファイルがダウンロードされる
3. GitHub でリポジトリを開き、「**Settings**」→「**Secrets and variables**」→「**Actions**」→「**New repository secret**」を押す
4. Name に `FIREBASE_SERVICE_ACCOUNT` と入力する。Secret には、ダウンロードした JSON ファイルの**中身をすべて**貼り付けて「Add secret」を押す
5. ダウンロードした JSON ファイルは、端末から削除する

⚠️ この JSON は Firebase を管理するための鍵です。GitHub のシークレット以外の場所（チャット、メモ、リポジトリのファイルなど）には絶対に貼らないでください。
万一漏れてしまったら、同じ「サービス アカウント」の画面から鍵を無効にできます（Google Cloud コンソールの「IAM と管理」→「サービス アカウント」→「キー」から削除）。

シークレットを設定するまでは、自動反映の処理は警告を出してスキップするだけです。テストは通常どおり実行されます。

## できること・できないこと

| 操作 | オーナー | メンバー | 招待されていない人 |
|---|---|---|---|
| 見る | ○ | ○ | × |
| ツアー・公演の追加、ツアー情報とセットリストの編集 | ○ | ○ | × |
| 自分の座席・写真・思い出・Tips を書く | ○ | ○ | × |
| 他の人の記録を書き換える | × | × | × |
| ツアー・公演の削除 | ○ | × | × |
| メンバーの追加・削除 | ○ | × | × |
